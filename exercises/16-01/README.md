# 16-01 코드를 꺼내 모으고 프로시저 목록 만들기

- **어느 장**: 16장 「16.1 폴더 안 xlsm 파일에서 코드만 뽑아내기」 · 「16.2 매크로마다 무슨 일을 하는지 한 줄 요약받기」
- **기본 과제** · 채점: 자동(auto)
- **시작 파일**: `practice/부서 관리대장.xlsm` — 원본은 열지 않습니다. 코드는 사본에서 꺼냅니다.
- **낼 파일**: `16-01_매크로목록.xlsx`

---

## 왜 하나

엑셀 파일 안의 코드는 엑셀을 열어야만 보입니다. **꺼내서 글 파일로 만들면** 검색도 되고 비교도 됩니다.
16장 본문은 공개 코드 여덟 파일로 연습하지만, 이 저장소에는 그 코드를 싣지 않았습니다.
이 과제는 4부에서 쓰던 〔대장m〕의 매크로 네 묶음으로 같은 일을 합니다. 코드를 꺼내고, 프로시저(Sub·Function 하나하나)마다 한 줄 요약을 붙인 목록을 만듭니다.

## 할 일

1. 16.1 의 꺼내기 시킬 말을 책 그대로 칩니다. 이 저장소에서는 「이 폴더」가 `practice` 폴더라고 알려 줍니다.

   ```prompt
   이 폴더의 매크로 파일들에서 VBA 코드를 꺼내서
   「코드모음」 폴더에 파일별로 저장해 줘.
   원본 파일은 건드리지 말고, 꺼낸 코드가 몇 파일 몇 줄인지 알려 줘.
   ```

   과제에서 붙인 말:

   ```prompt
   코드가 한 줄도 없는 시트 모듈은 꺼내지 마. 모듈마다 「모듈이름.bas」 파일 하나로 저장해 줘.
   꺼낼 때는 practice 의 원본을 열지 말고 사본을 만들어 거기서 꺼내 줘.
   ```

   > [그림 16-01-A] 코드를 꺼내도 되는지 묻는 화면 (촬영 예정)

2. 16.2 의 목록 시킬 말을 책 그대로 칩니다. ★ 마지막 줄을 빼지 않습니다.

   ```prompt
   코드모음 폴더의 파일들을 읽고, 프로시저마다 다음을 표로 만들어 줘.
   파일 이름 · 프로시저 이름 · 종류(Sub·Function) · 하는 일 한 줄 · 줄 수
   ★하는 일은 코드를 읽고 쓴 것만 적어 줘. 이름만 보고 짐작하지는 마.
   ```

3. 과제에서 붙인 말로 표를 시트로 만듭니다.

   ```prompt
   그 표를 「16-01_매크로목록.xlsx」 파일의 「매크로목록」 시트로 만들어 줘.
   1행은 머리글 — A 파일 · B 프로시저 · C 종류 · D 하는 일 · E 줄 수.
   A 칸에는 꺼낸 파일 이름을 「기록매크로.bas」처럼 확장자까지 적고, C 칸에는 Sub 나 Function 을 적어 줘.
   줄은 프로시저 이름 가나다순으로 정렬해 줘.
   ```

4. 채점합니다.

   ```
   python grader/check.py 16-01 16-01_매크로목록.xlsx
   ```

5. **내 매크로 파일로도 해 보기** — 회사나 집에 매크로가 든 파일이 있으면, 그 파일의 **사본**이 든 폴더에서 1~3번을 해 봅니다.

## 확인법 — 16장에서 배운 것

- 「꺼내는 것과 옮기는 것은 다르다」 — 원본 파일의 매크로는 그대로 두고 읽기용 사본을 만듭니다.
- 「★하는 일은 코드를 읽고 쓴 것만 적어 줘. 이름만 보고 짐작하지는 마.」 — 이름을 번역한 한 줄은 요약이 아닙니다. 이 파일에도 이름만 보면 모르는 것이 있습니다(월말정리가 실제로 무엇을 지우는지 같은 것).

## 채점기가 보는 것

| 항목 | 기대값은 어디서 오나 |
|---|---|
| 「매크로목록」 시트가 있다 | — |
| 줄마다 A 파일 · B 프로시저 · C 종류 | 채점기용 기대값은 `_expected.py` 가 원본 파일에서 코드를 따로 꺼내(엑셀을 열지 않고) 프로시저 선언을 찾아 가나다순으로 세운 것 |
| 목록 다음 줄이 비어 있다 | 빠지거나 더 붙은 프로시저가 없나 |
| practice 원본이 그대로다 | 원본 파일 지문 |

「하는 일」 칸이 채워졌는지, 이름 풀이가 아닌지는 채점 결과 아래 □ 목록으로 스스로 봅니다.
