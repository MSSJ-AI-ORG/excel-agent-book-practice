# 02-02 「저장했습니다」를 파일로 확인하기

- **어느 장**: 2장 「2.3 읽기만 하고 고치지 못하게 막아 두기」
- **응용 과제** · 채점: 자동(auto)
- **시작 파일**: `practice/이번 달 매출.xlsx` — 원본은 열지 않습니다. 파일 복사로 사본을 만들어 그 사본을 잠급니다.
- **낼 파일**: `02-02_잠금.xlsx` — 잠근 사본 그대로

---

## 왜 하나

2.3 에서 읽기 전용을 건 파일을 엑셀로 열어 B2 를 「태블릿」으로 바꾸고 저장을 시켰습니다.
오류는 안 났고, 엑셀은 저장됐다고 표시했습니다. 그런데 **파일은 안 바뀌었습니다.**

이 과제는 그 장면을 직접 겪어 봅니다. 그리고 「저장됐나」를 표시나 답이 아니라 **파일로** 판정합니다.
채점기는 잠근 사본이 원본과 바이트까지 같은지를 봅니다. 같으면 「태블릿」은 저장되지 않은 것입니다.

## 할 일

1. 저장소 폴더에서 `claude` 를 실행하고, 사본을 만들게 합니다. ‹과제에서 새로 붙인 시킬 말입니다.›

   ```prompt
   practice 폴더의 「이번 달 매출.xlsx」를 이 폴더에 파일 복사로 「02-02_잠금.xlsx」라는 이름으로 복사해 줘.
   엑셀로 열지는 말고, 원본은 건드리지 마.
   ```

2. 2.3 의 시킬 말로 사본을 잠급니다. 책의 시킬 말에서 **파일 이름만** 사본 이름으로 바꿨습니다.

   ```prompt
   02-02_잠금.xlsx 에 읽기 전용 속성을 걸어 줘.
   그리고 그 상태에서 파일을 읽는 것은 되는지 확인해 줘.
   ```

   > [그림 02-02-A] 읽기 전용을 걸고 읽기를 확인한 화면 (촬영 예정)

3. `02-02_잠금.xlsx` 를 엑셀로 엽니다. B2 를 「태블릿」으로 바꾸고 저장합니다(Ctrl+S 나 클로드에게 저장을 시킵니다).
   엑셀이 무엇이라고 표시하는지, 클로드가 무엇이라고 답하는지 **적어 둡니다.** 그다음 엑셀을 닫습니다.

4. 2.3 의 확인 문장을 책 그대로 칩니다.

   ```prompt
   방금 저장했다고 했는데, 파일을 다시 열어서 B2 값이 실제로 무엇인지 알려 줘.
   ```

5. **잠금을 풀지 않은 채로** 채점합니다.

   ```
   python grader/check.py 02-02 02-02_잠금.xlsx
   ```

6. 채점이 끝난 뒤에 잠금을 풉니다. 2.3 의 시킬 말을 책 그대로 칩니다.

   ```prompt
   읽기 전용을 풀어 줘. 풀기 전에 지금 이 파일이 정말 잠겨 있는지 먼저 확인해 줘.
   ```

## 확인법 — 2장에서 배운 것

- 「「했습니다」라는 답을 확인으로 쓰지 않는다」
- 「상태 표시가 아니라 실물로 판정한다」 — 그래서 채점기는 엑셀의 표시가 아니라 파일의 바이트를 댑니다.
- 「풀기 전에 확인을 붙이는 이유는, 이미 안 잠겨 있었던 경우를 걸러 내기 위해서다」

## 채점기가 보는 것

| 항목 | 기대값은 어디서 오나 |
|---|---|
| 매출!B2 가 원본 그대로다 | 원본 매출!B2 를 채점기가 읽는다 |
| 잠근 사본이 원본과 바이트까지 같다 | practice 의 원본 파일과 한 바이트씩 댄다 |
| practice 의 원본이 그대로다 | 원본 파일의 지문을 처음 받은 지문과 댄다 |

★ **읽기 전용 속성이 걸려 있는지는 채점기가 아직 보지 못합니다.** 파일을 오른쪽 클릭 → 속성에서 「읽기 전용」 칸을 직접 봅니다.

## 예시 파일

`solution/` 은 잠근 사본에서 위 과정을 그대로 거친 파일입니다. 이 파일을 만들 때도 책과 같은 일이 났습니다.
저장할 때 오류가 없었고 엑셀은 저장됐다고 표시했지만, 파일 지문은 원본과 같았고 다시 연 B2 는 원래 값이었습니다(`_build_log.txt`).
저장소에 넣으려고 읽기 전용 속성은 기록을 남긴 뒤에 풀었습니다. git 은 이 속성을 담지 않습니다.

`wrong/` 은 흔한 실수 하나 — **잠그지 않고** 같은 과정을 한 파일입니다. 이때는 「태블릿」이 실제로 저장됩니다.
