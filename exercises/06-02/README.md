# 06-02 짧게 고친 수식을 옛 수식과 대조하고 검사기를 검사하기

- **어느 장**: 6장 「6.3 뜻은 그대로 두고 수식 짧게 고치기」 · 「6.4 고친 수식이 옛 결과와 같은지 대조하기」
- **응용 과제** · 채점: 자동(auto)
- **시작 파일**: `practice/부서 관리대장.xlsx` — 원본은 열지 않습니다. 클로드에게 사본을 만들게 합니다.
- **낼 파일**: `06-02_대조.xlsx`

---

## 왜 하나

6.3 에서 정산 D열의 긴 수식을 짧게 고쳤고, 6.4 에서 옛 수식과 새 수식을 「대조」 시트에 나란히 놓았습니다.

차이가 0 으로 나오는 경우는 두 가지입니다. 두 수식이 정말 같거나, **대조하는 장치가 망가졌거나.**
그래서 한 줄만 일부러 틀리게 만들어, 대조가 그 줄을 잡아내는지 봅니다. 잡아낸 뒤에는 되돌립니다.

그리고 6.4 끝에서 본 일도 막아 둡니다. 「다른 행 수」를 세는 범위가 표 끝에서 멈춰 있으면, 새로 들어온 줄은 한 번도 세지 않습니다.

## 할 일

1. 저장소 폴더에서 `claude` 를 실행하고 사본을 만들게 합니다. 이 과제에서 새로 붙인 시킬 말입니다.

   ```prompt
   practice 폴더의 「부서 관리대장.xlsx」를 이 폴더에 복사해서 「06-02_대조.xlsx」로 만들어 줘.
   원본은 열지도 말고 건드리지도 마.
   앞으로 이 대화에서 「작업본」이라고 하면 이 사본을 가리키는 걸로 해 줘.
   ```

2. 6.3 의 시킬 말을 책 그대로 칩니다. 이 과제에서는 **마지막 한 줄을 더 붙입니다**(‹›).

   ```prompt
   정산 D3 수식에서 같은 SUMIF 가 세 번 반복되는데,
   B열에 이미 그 값이 있으니 그걸 참조하도록 고쳐 줘.
   결과가 달라질 수 있는 경우가 있으면 고치기 전에 먼저 알려 줘.
   ‹고친 수식은 보여만 주고 아직 시트에는 넣지 마.›
   ```

   6.2 에서 「넣지 마」라고 적었는데 파일이 바뀐 일이 있었습니다. 그래서 정산 시트가 그대로인지는 채점기가 파일로 봅니다.

3. 6.4 의 시킬 말을 책 그대로 칩니다. 이어서 「다른 행 수」를 둘 곳을 이 과제에서 새로 붙인 말로 정해 줍니다.

   ```prompt
   작업본에 「대조」 시트를 만들어 줘.
   정산 시트의 부서 세 곳(3~5행)에 대해,
   B열에는 지금 정산 D열에 들어 있는 옛 수식을 그대로 넣고,
   C열에는 6.3에서 받은 짧은 수식을 넣어 줘.
   D열에는 두 값의 차이를, E열에는 차이가 0이 아니면 "다름"을 표시해 줘.
   ★정산 시트 D열은 건드리지 마.
   ```

   ```prompt
   대조 시트 A3:A5 에는 부서 이름을 적고, G2 에 「다른 행 수」, G3 에 E열에서 "다름"을 세는 COUNTIF 수식을 넣어 줘.
   ```

4. **검사기를 검사합니다.** `06-02_대조.xlsx` 를 엑셀로 열고, 대조!C4(영업2팀) 수식 맨 뒤쪽의 `*0.5` 를 손으로 `*0.6` 으로 바꿉니다.
   영업2팀 줄에만 「다름」이 뜨고 G3 이 1 이 되는지 봅니다. 그다음 `*0.6` 을 다시 `*0.5` 로 되돌리고, G3 이 0 으로 돌아오는지 봅니다.

5. 「다른 행 수」의 범위가 표 끝에서 멈추지 않게 합니다. 이 과제에서 새로 붙인 시킬 말입니다.

   ```prompt
   대조!G3 의 COUNTIF 가 지금은 E3:E5 만 세고 있어.
   나중에 부서 줄이 아래로 늘어나도 세도록, 범위를 표 아래 넉넉한 줄(예: E100)까지 늘려 줘.
   ```

6. 엑셀로 열고 저장한 뒤 채점합니다.

   ```
   python grader/check.py 06-02 06-02_대조.xlsx
   ```

## 확인법 — 6.3·6.4 에서 배운 것

- 「결과가 달라질 수 있는 경우가 있으면 고치기 전에 먼저 알려 줘」 — 2번에서 `IFERROR` 를 뗐다는 말이 돌아왔는지 봅니다.
- 「일부러 틀린 값을 하나 심어 놓고, 대조가 그 행을 잡아내는지 확인하는 것」 — 4번.
- 「시트에 없던 경우를 일부러 만들어 넣어야 나온다」 — 5번. 범위가 E5 에서 끝나면 새 줄은 세지 않습니다.

## 채점기가 보는 것

| 항목 | 기대값은 어디서 오나 |
|---|---|
| 정산 시트(D열 옛 수식 포함)가 그대로다 | 원본 정산 시트와 칸마다 댄다 — 수식 칸은 수식 글자로 |
| 대조!B3:B5 옛 수식 값 | 채점기가 원본 대장·기준·이름 정의에서 부서마다 정산 규칙대로 다시 계산한다 |
| 대조!C3:C5 가 수식이고, 값이 옛 규칙과 같다 | 위와 같은 계산 |
| 대조!D3:D5 차이가 0 | — |
| 대조!G3 이 COUNTIF 수식이고 0 이다(되돌려 놓았다) | — |
| practice 의 원본이 그대로다 | 원본 파일의 지문을 처음 받은 지문과 댄다 |

## 스스로 확인할 것

- □ 대조!C3:C5 새 수식에는 IFERROR 가 없고, 정산!D3 옛 수식보다 짧다
- □ 대조!E3:E5(다른가)가 세 줄 모두 비어 있다
- □ C4 의 *0.5 를 *0.6 으로 바꿨을 때 영업2팀 한 줄에만 「다름」이 떴고 다른 행 수가 1 이 됐다
- □ *0.6 을 *0.5 로 되돌린 뒤 다른 행 수가 다시 0 이 됐다
- □ 다른 행 수 수식의 범위가 E5 에서 끝나지 않고 표 아래 새 줄까지 닿는다(예: E3:E100)

채점기는 아직 수식 «글자» 안의 범위와 함수가 없음을 보지 못합니다. 그래서 위 첫째·다섯째 줄은 수식 입력줄을 눌러 눈으로 봅니다.
