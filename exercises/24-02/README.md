# 24-02 정산액과 반올림, 규칙은 코드 밖에

- **어느 장**: 24장 「24.3 규칙을 코드 밖에 두기」 · 「24.4 값이 천 원 달랐다」
- **응용 과제** · 채점: 자동(auto) — 글 파일(CSV)을 채점합니다
- **시작 파일**: 24-01 에서 만든 프로그램
- **낼 파일**: 프로그램이 만든 `out/정산.csv`

---

## 왜 하나

24.3 에서 정산 규칙을 `rules.json` 으로 뺐고, 값마다 원래 엑셀 어디에서 왔는지 적었습니다.
그러다 기준 시트의 적용요율 열이 정산 수식에서 한 번도 안 쓰인다는 것을 찾았습니다. 「**고칠 것을 찾았어도 지금은 적어만 둔다.**」

24.4 에서는 정산액이 한 부서만 천 원 달랐습니다. 반올림하는 방법이 달라서였습니다.
엑셀 `ROUND` 는 딱 절반이면 0 에서 먼 쪽으로 가고, 파이썬의 기본 `round` 는 짝수 쪽으로 갑니다.

이 실습 파일에서도 **영업2팀의 반올림 전 값이 딱 절반(172,500)** 입니다. 파이썬 기본 반올림이면 여기서 천 원이 어긋납니다.

## 할 일

1. 24.3 의 규칙 파일 시킬 말을 책 그대로 칩니다.

   ```prompt
   정산 계산에 쓰는 값들을 rules.json 으로 빼 줘.
   기준요율·성과가산·건수 기준·정산 대상 부서·읽을 시트와 행 범위.
   그리고 각 값이 원래 엑셀 어디에서 온 것인지 같이 적어 줘.
   ```

2. 24.3 의 적용요율 시킬 말을 책 그대로 칩니다.

   ```prompt
   기준 시트의 적용요율 열이 정산 수식에서 쓰이는지 확인해 줘.
   안 쓰인다면 그 사실을 rules.json 주석에 적어 두고, 계산은 지금 수식 그대로 해 줘.
   ```

3. 정산액을 CSV 로 내게 합니다. 이 과제에서 새로 붙인 시킬 말입니다.

   ```prompt
   부서별 정산액을 out/정산.csv 로 내 줘.
   첫 줄은 「부서,정산액」, 그다음 정산 대상 부서마다 한 줄, 마지막 줄은 「합계,세 부서 정산액의 합」.
   숫자는 쉼표 없이 적어 줘.
   ```

4. 엑셀 값과 댑니다. 이 과제에서 새로 붙인 시킬 말입니다.

   ```prompt
   practice 의 「부서 관리대장.xlsx」를 이 폴더에 복사한 사본을 엑셀로 열어서, 전체 다시 계산한 뒤 정산 시트 D3:D5 와 D7 값을 읽어 와 줘.
   원본은 열지 마. 그 값과 out/정산.csv 를 줄마다 대 줘.
   ```

   한 줄이라도 다르면 24.4 의 반올림 시킬 말을 책 그대로 칩니다.

   ```prompt
   정산액 반올림이 엑셀 ROUND 와 같게 동작하도록 고쳐 줘.
   절반일 때 0 에서 먼 쪽으로 가야 해. 고친 뒤 세 부서 값을 다시 보여 줘.
   ```

   > [그림 24-02-A] 반올림을 고친 뒤 세 부서를 다시 대조한 화면 (촬영 예정)

   **고친 뒤 반드시 다시 댑니다.** 24.4 에서는 고친 결과가 반올림을 아예 안 해서 세 줄이 다 틀렸습니다.

5. 24.4 의 검산 칸 시킬 말을 책 그대로 칩니다.

   ```prompt
   엑셀이 낸 정산값 세 줄과 합계를 rules.json 의 검산 칸에 적어 줘.
   잰 날짜와 어떻게 쟀는지도 같이 적고,
   프로그램이 돌 때마다 그 값과 비교해서 다르면 알려 주게 해 줘.
   ```

6. 채점합니다. CSV 가 생긴 곳으로 경로를 바꿔 칩니다.

   ```
   python grader/check.py 24-02 out/정산.csv
   ```

## 확인법 — 24장에서 배운 것

- 「**어디서 온 값인지 안 적으면 반년 뒤에 못 고친다.**」 — rules.json 의 값마다 출처가 있는지 봅니다.
- 「**옮길 때는 지금 수식이 하는 대로 옮긴다.**」 — 적용요율이 아니라 기준요율로 계산했는지 봅니다.
- 「**「고쳤다」가 「맞다」가 아니다.**」 — 고친 뒤 다시 댔는지 봅니다.
- 「**이것이 21장 검사기를 프로그램 안에 넣은 것**이다.」 — 검산 칸이 돌 때마다 대 보는지 봅니다.

## 채점기가 보는 것

| 항목 | 기대값은 어디서 오나 |
|---|---|
| 첫 줄이 「부서,정산액」이다 | — |
| 부서 세 줄의 정산액 | 원본 대장·기준의 입력 칸에서 지금 정산 수식과 같은 규칙으로 계산하고 엑셀처럼 반올림한 값 |
| 합계 줄 = 세 줄의 합 | 같은 계산 |

CSV 를 채점하는 규칙은 숫자를 식으로 적을 수 없어 check.json 에 숫자를 적었습니다.
그 숫자는 `_expected.py` 가 원본에서 따로 계산합니다(파이썬 기본 `round` 였다면 어디가 달라지는지도 같이 찍습니다).

## 정답·오답 예시

- `solution/screen.py` · `solution/rules.json` — 규칙을 rules.json 에서 읽고, 엑셀 `ROUND` 와 같게 반올림해 `out/매출합계.csv` 와 `out/정산.csv` 를 내는 프로그램. rules.json 에는 값마다 출처, 적용요율이 안 쓰인다는 주석, 엑셀로 잰 검산값이 들어 있습니다. 돌린 결과 `solution/out/정산.csv` 는 전부 ✓.
- `wrong/make_wrong.py` · `wrong/out/정산.csv` — 같은 프로그램에서 **반올림만 파이썬 기본 `round` 로** 바꿔 돌린 결과. 영업2팀과 합계 두 항목만 ✗.
- `_expected.py` — 정산액을 원본에서 따로 계산한다. `_verify.txt` — 두 파일을 채점한 출력 원문.
