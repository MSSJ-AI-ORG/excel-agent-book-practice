# 20-01 자동 사본이 원본과 같은지 지문으로 확인하기

- **어느 장**: 20장 「20.1 실행 전 자동으로 사본 뜨게 하기」 · 「20.2 실제로 고치지 않고 결과만 먼저 보기」
- **기본 과제** · 채점: 자동(auto)
- **시작 파일**: `practice/부서 관리대장.xlsx` 를 **파일째 복사한** 작업본 — 원본은 열지 않습니다.
- **낼 파일**: `_백업` 폴더에 생긴 사본 하나 (이름 예: `부서 관리대장_20260922_1030.xlsx`)

---

## 왜 하나

20.1 에서 「사본을 만들었다는 답만으로는 부족하다. **같은지 확인한다.**」고 했습니다.
이 과제에서는 자동으로 뜬 사본을 채점기에 넣어, 원본과 바이트까지 같은지 지문으로 댑니다.

작업본을 **파일 복사**로 만들었다면 그 사본도 원본과 바이트까지 같아야 합니다.
엑셀로 열어 「다른 이름으로 저장」한 파일은 겉으로 같아 보여도 지문이 달라집니다. 채점기는 그것을 ✗ 로 잡습니다.

이어서 20.2 의 드라이런(실제로 고치지 않고 결과만 먼저 보기)을 하고, 정말 안 고쳤는지 직접 확인합니다.

## 할 일

1. 작업 폴더를 준비합니다. 아래는 이 과제에서 새로 붙인 시킬 말입니다.

   ```prompt
   practice 폴더의 「부서 관리대장.xlsx」를 이 폴더에 파일째 복사해 줘. 이름은 그대로 두고.
   엑셀로 열어서 다시 저장하지 말고, 파일 복사로만 해 줘. 원본은 건드리지 마.
   ```

2. 20.1 의 사본 규칙 시킬 말을 책 그대로 칩니다. 시각까지 넣는 줄을 빼지 않습니다.

   ```prompt
   앞으로 이 폴더의 엑셀 파일을 고치기 전에는 반드시 「_백업」 폴더에 사본을 먼저 만들어 줘.
   사본 이름은 「원래이름_YYYYMMDD_HHMM.xlsx」로 해 줘.
   사본을 만든 뒤에 고치고, 고친 뒤에 사본 경로를 알려 줘.
   ```

   아직 고칠 일이 없으니 사본을 하나 먼저 뜨게 합니다. 이 과제에서 새로 붙인 말입니다.

   ```prompt
   지금 규칙대로 작업 폴더의 「부서 관리대장.xlsx」 사본을 _백업 폴더에 하나 만들어 줘. 파일은 아직 고치지 마.
   ```

3. 20.1 의 해시 확인 시킬 말을 책 그대로 칩니다.

   ```prompt
   방금 만든 사본과 원본의 해시값을 각각 구해서 같은지 알려 줘.
   ```

   > [그림 20-01-A] 두 해시값을 나란히 보여 주는 화면 (촬영 예정)

   책의 표에 찍힌 값(`2a919df4…`)은 책을 쓸 때 쓴 파일의 지문입니다.
   이 저장소의 원본 지문은 `practice/MANIFEST.json` 에 적힌 값(`6a0b6808…` 로 시작)입니다. 파일이 조금 달라서 지문도 다릅니다.

4. 20.1 의 멈춤 시킬 말을 책 그대로 칩니다.

   ```prompt
   사본 만들기가 실패하면 원본 작업을 시작하지 말고 멈춰서 알려 줘.
   폴더가 없거나 권한이 없거나 디스크가 꽉 찬 경우가 있을 수 있어.
   ```

5. 20.2 의 드라이런 시킬 말을 책 그대로 칩니다. 「실제로 고치지는 말고」 줄을 빼지 않습니다.

   ```prompt
   대장에서 부서 이름의 띄어쓰기를 전부 없애려고 해.
   ★실제로 고치지는 말고, 고치면 어떻게 되는지만 보여 줘.
   ① 몇 개 셀이 바뀌나
   ② 바뀌기 전과 후를 나란히
   ③ 그 결과 정산 시트의 어느 값이 얼마로 바뀌나
   ```

   > [그림 20-01-B] 드라이런 결과 — 파일은 그대로 두고 목록만 보여 준 화면 (촬영 예정)

6. 드라이런이 정말 안 고쳤는지 확인합니다. 20.2 의 시킬 말을 책 그대로 칩니다.

   ```prompt
   방금 드라이런 뒤에 파일이 실제로 바뀌었는지 확인해 줘.
   파일 수정 시각과 대장 B열 값 두 개를 보여 줘.
   ```

   대장 B5 가 「영업 1팀」(띄어쓰기 있음) 그대로면 맞습니다.

7. `_백업` 폴더에 생긴 사본을 채점합니다. 파일 이름은 여러분 폴더에 생긴 이름으로 바꿔 칩니다.

   ```
   python grader/check.py 20-01 "_백업/부서 관리대장_20260922_1030.xlsx"
   ```

## 확인법 — 20장에서 배운 것

- 「**파일 크기가 같아도 내용이 다를 수 있으므로, 크기가 아니라 해시로 본다.**」 — 채점기도 지문으로 댑니다.
- 「**시각까지 넣는다.**」 — 사본 이름에 날짜와 시각이 다 들어 있는지 스스로 봅니다.
- 「**「안 고쳤습니다」라는 답을 확인으로 쓰지 않는다.**」 — 6번에서 파일 수정 시각과 B열 값을 직접 받았는지 봅니다.

## 채점기가 보는 것

| 항목 | 기대값은 어디서 오나 |
|---|---|
| 낸 사본이 원본과 바이트까지 같다 | practice 원본 파일 그 자체와 지문으로 댄다 |
| practice 의 원본이 그대로다 | 원본 파일의 지문 |

사본 이름 모양(`_숫자8자리_숫자4자리.xlsx`)과 드라이런 뒤 B5 는 채점기가 아직 보지 못합니다. 채점 결과 아래 확인 목록으로 나옵니다.

## 정답·오답 예시

- `solution/부서 관리대장_20260922_0002.xlsx` — 원본을 파일 복사로 뜬 사본. 전부 ✓.
- `wrong/부서 관리대장_20260922_0002.xlsx` — 원본 사본을 **엑셀로 열어 다른 이름으로 저장**해 만든 사본. 시트와 값은 같아 보여도 지문이 달라 「바이트까지 같다」 항목만 ✗.
- `_verify.txt` — 두 파일을 채점한 출력 원문.
