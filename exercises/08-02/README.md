# 08-02 표로 바꾸고 20행을 넣어 정산이 따라오는지 보기

- **어느 장**: 8장 「8.4 파일이 바뀌어도 안 깨지게 기준 잡기」
- **응용 과제** · 채점: 자동(auto)
- **시작 파일**: `practice/부서 관리대장.xlsx` — 원본은 열지 않습니다. 클로드에게 사본을 만들게 합니다.
- **낼 파일**: `08-02_표.xlsx`

---

## 왜 하나

정산 시트의 수식은 대장 4행부터 19행까지만 봅니다. 20행에 새 거래를 넣으면 정산에 들어가지 않고, 오류도 경고도 없이 그냥 빠집니다.

8.4 에서는 대장의 데이터 구간을 표로 바꿨습니다. 그러자 표가 20행까지 넓어질 때 정산 수식의 범위도 19 에서 20 으로 스스로 늘어났습니다.
이 과제에서 그 일을 직접 만들어 봅니다. 표로 바꾸기 **전과 뒤에 각각** 20행을 넣어 봅니다.

## 할 일

1. 저장소 폴더에서 `claude` 를 실행하고 사본을 만들게 합니다. 이 과제에서 새로 붙인 시킬 말입니다.

   ```prompt
   practice 폴더의 「부서 관리대장.xlsx」를 이 폴더에 복사해서 「08-02_표.xlsx」로 만들어 줘.
   원본은 열지도 말고 건드리지도 마.
   앞으로 이 대화에서 「작업본」이라고 하면 이 사본을 가리키는 걸로 해 줘.
   ```

2. 표로 바꾸기 전에 20행을 넣어 봅니다. 이 과제에서 새로 붙인 시킬 말입니다.

   ```prompt
   작업본 대장 20행에 일자 「2026-06-04」, 부서 「영업1팀」, 구분 「신규」, 금액 2000000 인 거래를 한 줄 넣고,
   정산!B3 값이 넣기 전과 달라졌는지 알려 줘.
   확인한 뒤에는 20행을 다시 비워 줘.
   ```

3. 8.4 의 시킬 말을 책 그대로 칩니다.

   ```prompt
   대장의 데이터 구간(3행 머리글부터)을 표로 바꿔 줘. 표 이름은 「대장표」로 해 줘.
   바꾼 뒤에 정산 값이 달라지는지 확인해서 알려 줘.
   ```

4. 다시 20행을 넣습니다. 이 과제에서 새로 붙인 시킬 말입니다. 이번에는 지우지 않습니다.

   ```prompt
   대장 20행에 2번과 같은 거래(2026-06-04 · 영업1팀 · 신규 · 2000000)를 다시 넣어 줘.
   표가 20행까지 넓어졌는지, 정산!B3 의 값과 수식이 어떻게 바뀌었는지 알려 줘. 이번에는 지우지 마.
   ```

5. `08-02_표.xlsx` 를 엑셀로 엽니다. 정산!B3 을 눌러 수식 입력줄의 범위가 `$B$4:$B$20` 인지 봅니다. 저장하고 닫습니다.

6. 채점합니다.

   ```
   python grader/check.py 08-02 08-02_표.xlsx
   ```

## 확인법 — 8.4 에서 배운 것

- 「표로 만드는 것이 수식을 고치는 것보다 낫다」 — 수식을 한 글자도 안 고쳤는데 범위가 늘었는지 5번에서 봅니다.
- 2번에서 정산!B3 이 그대로였다면, 그것이 이 절이 말한 «그냥 빠지는» 모습입니다.

## 채점기가 보는 것

| 항목 | 기대값은 어디서 오나 |
|---|---|
| 대장!B20 이 「영업1팀」, D20 이 200만 | 시킬 말의 값 |
| 정산!B3 = 20행까지 더한 영업1팀 매출합계 | 채점기가 **제출 파일** 대장 B4:B20 에서 정확히 「영업1팀」인 줄의 D 를 다시 더한다 |
| 정산!B3 = 원본 영업1팀 합계 + 200만 | 채점기가 원본 대장에서 정확히 「영업1팀」인 줄의 D 를 더하고, 시킨 금액 200만을 더한다 |
| 대장 4~19행이 원본과 같다 | 원본 대장과 칸마다 댄다 |
| practice 의 원본이 그대로다 | 원본 파일의 지문을 처음 받은 지문과 댄다 |

## 스스로 확인할 것

- □ 표로 바꾸기 전에 20행을 넣었을 때 정산!B3 이 그대로(5,270,000)인 것을 보고 그 줄을 지웠다
- □ 대장에 「대장표」라는 표가 있고 범위가 A3:F20 이다([수식] - [이름 관리자]에 표 이름과 범위가 보인다)
- □ 정산!B3 수식이 대장!$B$4:$B$20 으로 스스로 바뀌어 있다

## 막혔을 때

`solution/` 에 정답 예시 파일이, `wrong/` 에 흔한 실수 하나(표로 바꾸지 않고 20행만 다시 넣은 파일)가 있습니다.
정산!B3 두 항목이 함께 ✗ 가 됩니다. 채점기 출력 원문은 [`_verify.txt`](_verify.txt) 에 있습니다.
