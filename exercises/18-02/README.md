# 18-02 규칙대로, 겹치지 않는 이름으로 새 매크로 받기

- **어느 장**: 18장 「18.1 규칙 문서를 근거로 새 매크로 요청하기」 · 「18.3 기존 매크로와 이름·범위가 겹치지 않게 하기」
- **응용 과제** · 채점: 자동(auto) — 코드 글 파일을 채점합니다
- **시작 파일**: `practice/부서 관리대장.xlsm` — 원본은 열지 않습니다. 사본에서 합니다.
- **낼 파일**: `부서별합계저장.bas` (새 매크로가 든 모듈을 내보낸 글 파일)

---

## 왜 하나

새 매크로를 하나 만듭니다. 대장에서 부서별 합계를 내고 결과를 새 파일로 저장하는 일입니다.
18장의 순서는 이렇습니다 — 목록에서 먼저 찾고, 만들기 전에 단계를 받고, 규칙 문서를 읽고 짓게 하고, 지키지 못한 것을 먼저 말하게 하고, 이름이 겹치지 않는지 센다.
여기에 15장에서 배운 저장 규칙(덮어쓰기 전에 멈추기, 경고를 끄지 않기)과 7장·14장의 부서 이름 공백 문제가 함께 걸립니다.

## 할 일

1. `practice/부서 관리대장.xlsm` 을 작업 폴더에 `18-02_작업.xlsm` 으로 복사하게 합니다. 원본은 열지 않게 합니다.

2. 18.1 의 첫 시킬 말을 책 그대로 칩니다(16-01·16-02 의 매크로목록이 있으면 그것을 씁니다).

   ```prompt
   매크로목록에서 「부서별 합계를 내고 파일로 저장하는」 일을 하는 것이 이미 있는지 찾아 줘.
   ```

3. 18.1 의 단계 시킬 말을 책 그대로 칩니다.

   ```prompt
   코드를 만들기 전에, 이 매크로가 무엇을 할 것인지 단계로 적어 줘.
   어느 시트를 읽고, 무엇을 계산하고, 어디에 저장하는지.
   ★아직 코드는 쓰지 마.
   ```

4. 18.1 의 만들기 시킬 말을 책 그대로 칩니다. 17-02 를 아직 안 했으면 과제에서 붙인 말을 함께 칩니다.

   ```prompt
   부서별 합계를 내고 결과를 새 파일로 저장하는 매크로를 만들어 줘.
   ★코드규칙.md 와 용어사전.md 를 먼저 읽고, 그 규칙대로 지어 줘.
   그리고 규칙 중에 지키지 못한 것이 있으면 왜 못 지켰는지 알려 줘.
   ```

   과제에서 붙인 말(코드규칙.md 가 없을 때 대신 쓰는 규칙):

   ```prompt
   규칙 — 모듈 맨 위에 Option Explicit. Sub·Function 바로 윗줄에는 하는 일을 적은 주석 한 줄.
   부서 이름은 공백을 모두 빼고 댄다(「영업 1팀」과 「영업1팀」은 같은 부서).
   저장하기 전에 같은 이름 파일이 있는지 Dir 로 보고, 있으면 덮어쓰지 말고 멈춘다. DisplayAlerts 는 끄지 않는다.
   ```

5. 18.3 의 시킬 말을 책 그대로 칩니다(〔대장m〕의 이름은 95개가 아니라 여섯 개입니다).

   ```prompt
   새 매크로 이름을 정하기 전에, 지금 쓰이는 이름 95개와 겹치지 않는지 확인해 줘.
   그리고 이름 짓는 방식(첫 글자 소문자)도 지켜 줘.
   ```

   과제에서 붙인 말:

   ```prompt
   새 매크로는 새 모듈에 넣고, 모듈 이름은 프로시저 이름과 다르게 지어 줘.
   ```

   모듈 이름과 프로시저 이름이 같으면, 이 과제를 만들며 엑셀 COM 으로 그 매크로를 부를 때 「매크로를 실행할 수 없습니다」가 나와 돌리지 못했습니다. 모듈 이름을 바꾸자 돌았습니다.

6. 사본에서 새 매크로를 한 번 돌려, 새 파일의 부서별 합이 대장과 맞는지 봅니다.

   > [그림 18-02-A] 새 매크로를 돌려도 되는지 묻는 화면 (촬영 예정)

7. VBA 편집기에서 새 모듈을 고른 뒤 **[파일] - [파일 내보내기]** 로 저장하고, 파일 이름을 `부서별합계저장.bas` 로 합니다.

8. 채점합니다.

   ```
   python grader/check.py 18-02 부서별합계저장.bas
   ```

## 확인법 — 18장에서 배운 것

- 「지키지 못한 것을 먼저 말하게 한다」 — 안 그러면 지킨 것처럼 보이는 코드가 옵니다.
- 「겹침 검사와 규칙 검사를 같이 한다」 — 따로 하면 하나를 빠뜨립니다.
- 이름이 겹치면 오류가 안 나고 **그냥 다른 쪽이 돕니다.**

## 채점기가 보는 것

채점기는 주석 줄을 빼고 코드를 봅니다(R4 항목만 주석 줄을 봅니다).

| 항목 | 무엇을 보나 |
|---|---|
| `Sub` 가 있다 · `Option Explicit` 이 있다(R2) | — |
| `Sub`·`Function` 줄 바로 윗줄이 `'` 뒤에 글자가 있는 주석이다(R4) | — |
| 새 프로시저 이름이 원본 매크로 이름과 겹치지 않는다 | 겹치면 안 되는 이름은 `_expected.py` 가 원본 파일의 코드에서 모은 여섯 개 |
| `SaveAs` 가 있고, 그보다 앞에 `Dir(` 가 있다 | 덮어쓰기 전에 같은 이름 파일을 보나 |
| `DisplayAlerts = False` 가 없다 | 경고를 끄지 않나 |
| `Replace(…, " ", "")` 가 있다 | 부서 이름의 공백을 모두 빼고 대나 |

## 여기서 쓴 엑셀 기능

VBA `Sub`·`Function` · `Option Explicit` · `Replace` · `Dir` · `Workbooks.Add` · `SaveAs` · 모듈 이름 · [파일 내보내기]

## 만드는 사람을 위한 기록

- `solution/부서별합계저장.bas`: 〔대장m〕 사본에 엑셀 COM 으로 새 모듈(「새매크로」)을 더해 `부서별합계저장`·`저장경로` 를 넣고 내보낸 것.
  사본을 빈 폴더로 옮겨 돌렸더니 `부서별합계_YYYYMMDD_HHMM.xlsx` 가 생겼고, 부서별 합(영업1팀 7,910,000 · 영업2팀 13,450,000 · 영업3팀 12,960,000)이 원본 대장에서 파이썬으로 따로 센 합과 같았다.
  처음에 모듈 이름을 프로시저 이름과 같은 「부서별합계저장」으로 했을 때 `Application.Run` 이 「매크로를 실행할 수 없습니다」로 실패했다 — 모듈 이름을 바꾸자 돌았다.
- `wrong/부서별합계저장.bas`: 흔한 실수 하나 — 같은 이름 파일이 있는지 보지 않고 바로 저장한다(`Dir(` 확인 없음). 그 항목 하나만 ✗.
- 카탈로그의 `vba_names_unique`·`text_order` 규칙은 채점기에 없어서, 원본에서 모은 이름 목록을 넣은 정규식과 「처음부터 `Dir(` 없이 `SaveAs` 에 닿는 부분이 없다」 정규식으로 대신했다.
- 채점 출력 원문: `_verify.txt`
